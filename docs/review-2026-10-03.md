# Hooversion reliability review — October 3, 2026

## Scope and baseline

Reviewed main at `f0a37cca22997993ca6416010b81ca197a3ac580` (v1.1.2):
configuration, commit parsing/routing, manifests, Git wrappers, release execution
and recovery, GitHub HTTP/upload/authentication, artifact verification, App
execution/spooling, composite actions, and CI. Tracking issue: #45.

The initial macOS race suite failed in the App spool tests because macOS temp
paths contain the `/var` symlink, and in CLI output assertions because
`os.Getwd()` returns the canonical path. Other package suites passed. These
failures exposed missing macOS coverage; production spool symlink rejection is
preserved.

## Implemented findings

| Area | Reproduced behavior | Change |
| --- | --- | --- |
| Configuration | Unknown fields, extra YAML documents, unsupported types, constant/unknown-placeholder tag templates, conflicting managed paths, and unsafe asset contracts were accepted. | Strict single-document decoding, explicit type/template validation, distinct release file ownership, dedicated outputs, relative assets with unique basenames, and symlink-component checks. |
| Filesystem writes | Manifest writes followed final symlinks and updated hardlink targets; direct overwrites and Cargo.lock truncation could damage individual files. A symlinked output directory could redirect cleanup and publication state outside the checkout. | Bounded regular-file reads, synced sibling writes and rename, permission preservation, protected output roots, and actual Windows reparse-point opens. |
| Git history | Invalid revisions became an empty result; option-like revisions could expand collection. CLI already validated refs, but internal history collection was not fail-closed. | Resolve both endpoints to commits, reject failures, pass immutable hashes to rev-list, and separate revisions from paths. |
| Git filenames | Git's quoted/newline output lost Unicode, tab, and newline filenames; managed paths were compared against quoted strings. A managed destination could obscure an unmanaged rename source. | NUL-delimited filename/status parsing and checks of both rename endpoints. |
| Remote refs | Transport errors looked like absent remote refs. | Network probe errors propagate; missing refs remain a separate state. |
| Environment isolation | Detached branch resolution and GitHub Actions output writes used parent CI state even with an explicit child environment. | Explicit environments determine branch metadata, hook shell, credential fallback, and output destination; an empty environment stays isolated. |
| Publication | Publishing temporarily changed the process working directory. | Uploads take an explicit checkout root; publication leaves global cwd unchanged. |
| GitHub API | Installation token parsing accepted missing tokens, trailing JSON, and unbounded responses. Calls lacked a default timeout and authenticated mutations could redirect. | Bounded parsing/error reads, token validation, finite request timeouts, mutation redirect rejection, and credential removal on cross-origin download redirects. |
| Release source | Hooks could move or commit HEAD after initial source validation and still receive a release tag. | Recheck local source SHA after beforeRelease and afterVersion hooks. |
| Versioning/routing | Integer overflow was ignored; bumps could wrap negative. Invalid suffix identifiers were accepted. An independent `none` rule caused a patch bump, and `..data` paths lost package ownership. | Checked parsing/bumping, identifier validation, explicit none mapping, and component-aware containment. |
| Commit lint | The 100-character limit counted UTF-8 bytes. | Count Unicode code points. |
| Migration | Legacy `github: false` failed decoding; rendering a disabled section also produced invalid modern YAML. | Translate the legacy boolean and serialize `github.enabled: false`, with a reload test. |
| Artifact verification | Archive checks stopped at the first LICENSE; later traversal/corruption escaped inspection. ZIP symlinks could satisfy the license check. Windows drive paths passed Unix checks. | Complete archive/CRC inspection, regular LICENSE requirements, cross-platform path validation, and bounded entry/data budgets. |
| Maintenance | Dead installation/parser paths and duplicate unused release helpers obscured active behavior. | Remove unused code, clean static-analysis findings, and expose App version/help without startup credentials. |
| CI | No macOS job, Linux did not check the declared minimum Go version, and Windows omitted shared filesystem/manifest/output code. | Linux uses go.mod; macOS runs the race suite on stable Go; Windows exercises the affected file packages. |

## Compatibility

Normal valid configurations and release outputs retain their shape. The
following formerly accepted inputs now fail intentionally:

- Unknown fields, extra documents, unsupported package types, unsafe paths,
  shared manifest/changelog destinations, and colliding asset basenames.
- Tag formats with zero/multiple version placeholders or unknown placeholders.
- Symlinked configuration/manifest files, symlink components inside configured
  release paths, and oversized input files. Config/stale outputs are capped at
  1 MiB; manifests are capped at 16 MiB.
- Malformed prerelease/build identifiers, overflowing version components, and
  overflow-producing bumps. Leading zeros in core versions remain supported.
- Hooks that change HEAD during release execution.
- Redirected authenticated mutations and malformed token responses.

Archive license verification is stricter and reads every entry. A release with
a valid early license and later corrupt/unsafe content now fails.

## Remaining architecture priorities

1. **Whole-release transaction recovery.** Individual atomic writes do not
   journal or roll back a multi-file release. Hook and pre-push failures can
   leave changed files, commits, or partial local tag sets. Design explicit
   phases, recovery state, and failure-injection tests before changing those
   semantics.
2. **Descriptor-rooted mutation and checkout ownership.** Config/preflight
   checks reject existing symlink components, but they are not a general defense
   against another local process swapping directories during execution. Extend
   the App spool's rooted-filesystem discipline to repository mutation, and
   define a release lock.
3. **Runner cancellation and bounded concurrency.** The App runner still has a
   global execution mutex, while the queue models separate repository/ref
   chains. Git and hook subprocesses still lack execution deadlines. Introduce
   cancellation and an explicit worker budget before widening concurrency.
4. **Manifest grammar and discovery.** Rust/Python support still uses targeted
   TOML/requirement parsing. Audit Cargo workspace globs, inherited package
   versions, workspace exclusions, inline/quoted/commented TOML constructs, and
   richer Python requirement forms with ecosystem fixtures before broadening
   the advertised support.
5. **History scaling and published asset recovery.** Collection still launches
   Git subprocesses per commit. Benchmark representative large histories and
   batch metadata without losing exact path identity. Existing asset recovery
   trusts names; a follow-up should bind reuse to remote size/digest and handle
   paginated asset inventories explicitly.

This review does not treat a green CI run as a new published release. The
implementation must be merged and released before downstream users receive it.
